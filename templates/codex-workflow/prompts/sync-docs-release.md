create-release mode publishes a release immediately from the current main tip. This is real and irreversible.

1. Preconditions: git status is clean, and HEAD equals the tip of origin main by SHA (the checkout may be detached-HEAD). Run git fetch origin main, then compare git rev-parse HEAD with git rev-parse origin/main. If they differ, stop and post a comment saying the checkout is not on the current tip of origin main.
2. Inspect tags with git tag --sort -v:refname and review the commits since the latest tag with git log.
3. Determine the semantic version bump and state the rationale in plain words, as above, and name the bump category the commits require. Before you settle on it, read the manifest versions with the discovery and classification rules of step 4. When every applicable field resolves to one value V, and V is the next patch, minor, or major version after the latest semver tag, release V instead and state that the manifests chose it, but only when the bump category of V is at least the category the commits require (major above minor above patch). When V is a smaller bump, stop before step 5, create no tag, and post a comment that names V, the required category, and the commits that require it. When no semver tag exists, release the value the fields resolve to. A pubspec.yaml value counts without its + suffix. When the fields do not resolve to one such V, keep the bump from the commits. 4. Verify the manifest versions against the release version before you publish. The check runs on the checked-out commit that step 1 proved equal to the tip of origin main. The release version is the X.Y.Z from step 3, and a manifest value matches only when it equals X.Y.Z without the v prefix. The one exception is pubspec.yaml: every version comparison in steps 3 and 4, meaning the applicability tests for nested manifests, the higher-than test, and the match test, uses only the part of its value before any + suffix, because that suffix is a build number this check never reads.

A read failure is never an absent field. An inherited value is resolved only when the file that defines it was read in this pass and holds a literal. Two standard derivations are the exception.
