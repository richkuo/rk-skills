# Contract inventory: loop / validate pipeline rules

Scope: the loop/validate skill families ([#64](https://github.com/richkuo/rk-skills/issues/64)) plus the plan producers and consumers that feed them.

Each row names a shared rule, its owner, the consumers that must state it, the semantics the guard checks, the divergence it allows, and the guard test. Guards check thresholds, stop conditions, and field names, never exact strings. The owner file holds the full rule.

## How to update a guarded rule

Edit every consumer listed for the row in the same change (no generator exists for `SKILL.md` prose, except the pr-review format copies: edit only the skill's `## Review contract`, then run `bun bin/sync-pr-review.mjs --write`), record an intentional divergence in the row and the guard's exception list, run `bun test`, and keep the row's consumers in sync with the guard's.

## Intentional exceptions

`fable-validate-fableplan-loop`, `fable-validate-fableplan`, and `fableplan-loop` have no skip-below-71 gate by design; the guard requires them to state the missing gate and never the skip instruction. `validate-issue` and `fable-validate` own claim-tracing and scoring and never restate the review-cycle threshold, score gate, or duplicate stop; both still consume the issue-edit attribution verb row.

## Out of scope for the pipeline guard

`workflows/milestone-pipeline.js` `maxReviewCycles` (default **5**) is a workflow arg matching the skill threshold today, and neither changes the other; `skills/milestone-workflow/SKILL.md` only documents it; `tests/milestone-pipeline.test.js` exercises the harness. The workflow stays a consumer of the rows that name it.
