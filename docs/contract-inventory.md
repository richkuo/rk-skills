# Contract inventory: loop / validate pipeline rules

Scope: the loop/validate skill families ([#64](https://github.com/richkuo/rk-skills/issues/64)) plus the plan-producer/plan-consumer family that hands those chains their plans.

Each row names a shared rule, its owner, the consumers that must state it, the semantics the guard checks, the divergence it allows, and the guard test. Guards check thresholds, stop conditions, and field names in the procedure body, never exact strings. The full rule lives in its owner file.

## How to update a guarded rule

Edit every consumer listed for the row in the same change (there is no generator for `SKILL.md` prose), record an intentional divergence in the row and in the guard's exception list, run `bun test`, and keep the row's consumer list in sync with the guard's.

## Intentional exceptions

`fable-validate-fableplan-loop`, `fable-validate-fableplan`, and `fableplan-loop` have no skip-below-71 gate by design; the guard requires them to state the missing gate and never requires the skip instruction there. `validate-issue` and `fable-validate` own claim-tracing and scoring and never restate the review-cycle threshold, score gate, or duplicate stop; both remain consumers of the issue-edit attribution verb row.

## Out of scope for the pipeline guard

`workflows/milestone-pipeline.js` `maxReviewCycles` (default **5**) is a workflow arg that matches the skill threshold today, though changing one never changes the other; `skills/milestone-workflow/SKILL.md` only documents that arg; `tests/milestone-pipeline.test.js` exercises the workflow harness. `workflows/milestone-pipeline.js` stays a consumer of the rows that name it.
