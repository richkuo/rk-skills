# Agent guide contract

A project whose agent guides are generated by a project command states that in its root `CLAUDE.md`. This file owns the statement form and the rule that every writer of agent guides follows. Read it only when `SKILL.md` sends you here.

## Statement form

The block starts at a heading line that is exactly `## Agent guide contract` (no trailing space), outside a code fence, once in the file. It ends at the next heading or at the end of the file.

```
## Agent guide contract
- Generated: `AGENTS.md`
- Sources: `CLAUDE.md`, `.claude/rules/*.md`
- Regenerate: `python3 -I tools/build_agent_guide.py`
- Verify: `bash tools/check_agent_guide.sh`
- Command files: `tools/`
```

- Each non-blank line in the block is one of the five labels, each label once. Any other line, a missing label, or a second contract heading makes the statement malformed.
- A value is one or more backtick spans joined by a comma and a space. `Regenerate` and `Verify` take one span each.
- Paths use only `A-Z a-z 0-9 . _ / * -`, never start with a slash, and hold no empty, `.`, `..`, or `.git` segment. `Generated` takes literal paths only, and never `CLAUDE.md`. `Sources` and `Command files` accept `*` inside one segment. `Command files` also accepts a directory with a trailing slash, which covers every file below it, tracked or not.
- Commands use only `A-Z a-z 0-9 space . _ / = : @ % + -`, with single spaces. They run with no shell: the runner splits them on spaces. A command that needs more goes into a script.
- `Command files` lists every file the two commands execute. List a directory when in doubt: a helper that the generator loads and that the list omits is not compared.
- A generated path never matches a `Sources` or a `Command files` entry, and no file matches both a `Sources` and a `Command files` entry.
- **Trusted read.** Every writer reads the statement from `CLAUDE.md` at the default-branch commit as file text, never from a pull request, a session branch, or the work tree.
- **Permit rule (workflows).** A workflow runs a command only when the caller's `guide_contract_permit` input lists that exact command as a plain comma-separated entry. A wildcard entry or a `Bash(...)` entry does not permit it, and `extra_allowed_tools` permits nothing. The permit never reaches an agent allowlist, and when a contract is stated the workflows remove the entries `Bash(<regenerate command>)` and `Bash(<verify command>)` from every agent allowlist. A permit that holds one or more entries after the split on commas and the removal of blank entries makes the contract mandatory for that caller, also when no entry permits a command. When a workflow reads no contract at the default-branch commit (no trusted commit, a `CLAUDE.md` that is missing or has no exact heading line, or a heading only inside a code fence), the `sync-docs` and `sync-release` flows stop before the agent starts and the post-implementation revision stops, each with an issue comment that states the reason, and no legacy guide editor runs for that caller. A permit of blank entries only is no permit.
- **Size.** A generated guide is exempt from the rule that ties the `CLAUDE.md` and `AGENTS.md` policies together and from the fallback threshold. Measure it only against a limit the repository states for that path by name.

## Writer rule

Every writer of agent guides (this skill, both workflow sync prompts, and both post-implementation steps) follows this order:

1. Read the trusted statement.
2. Never edit a stated generated file, a stated command file, or the contract block.
3. Among the agent guide files, edit the stated sources only, under the step 6 placement rule. Other documentation files follow the normal procedure.
4. Run the regenerate command after the last edit and before the size check, then the verify command.
5. Accept only stated generated files as generator output, and a verify command that changes nothing.
6. On any failure, stop before any commit.

## In this skill

- **Command check.** Before each run of a command, `git diff --quiet "$T0" -- <each Command files entry>` must report no change, and `git status --porcelain -- <each Command files entry>` must print nothing. Otherwise the sync is **blocked**: a changed command file is code that the default branch did not review.
- **Step 3.** Record each stated generated guide under the **Size** rule above. The pair rule and the fallback apply to the stated sources as written.
- **Step 6.** Never open a stated generated file for writing. When `AGENTS.md` is a stated generated file, the step 6 mirror does not apply to it: its content comes from the regenerate command.
- **Regenerate and verify.** Apply Writer rule item 4 from the worktree root before step 10, and again after the last condense edit of step 10. Compare `git status --porcelain` before and after each command to apply item 5; each changed generated file must be a regular file.
- **Condense.** A condense pass keeps the contract block byte for byte.
- **Step 12.** Stage the edited sources, the other docs this sync edited, and only the stated generated files, by name.
- **Blocked outcome.** A malformed statement, a changed command file, a regenerate or verify command that fails or that you cannot run, a regenerate command that changes a file outside the stated generated set, and a verify command that changes a file each make the sync **blocked** (step 11's outcome): report the cause, the command, its exit status, and its output, make no commit, push, or PR, and keep the worktree and its edits for the owner.
